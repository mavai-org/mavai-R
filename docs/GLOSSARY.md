# Glossary

Terminology used across the mavai project family. Terms are defined in the
context of the distributional contract methodology; framework-specific
annotations and APIs may vary by implementation.

| Term                                        | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
|---------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Architectural Discharge**                 | How a **categorical clause** is met: a separate component — a guardrail, deterministic filter, hard schema gate or refusal classifier — is interposed between the stochastic generator and the consumer of its output, and its presence is the contract's answer. Where that boundary is itself probabilistic, its performance re-enters the contract as ordinary rate-bounded clauses (typically sensitivity and specificity over adversarial samplings). Licenses conditional claims only; it never proves the categorical clause. See **Conditional Containment Model**; [Statistical Companion](STATISTICAL-COMPANION.md) §"Clause Forms", §1.4.5b.                                                                                                                                                                                                                             |
| **Baseline Expiration**                     | An optional validity period (expiration window) declared on a baseline, beyond which it is no longer admitted as a reference. Catches unknown, gradual drift that covariates cannot; graduated warnings are issued as expiry approaches. Under VERIFICATION, a baseline expired beyond a stated grace window is a major caveat. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.5.5, §8.4.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Baseline Selection**                      | The process of choosing the baseline a probabilistic test resolves against. A baseline is indexed by its service-contract identity (which carries the structural reference; in implementations, the **Footprint**) and its resolved covariate values; the test selects the baseline whose index matches its own. Where no baseline matches, the divergence is reported on the verdict, or the test declines to resolve. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.5.2, §1.5.3, §8.4.1.                                                                                                                                                                                                                                                                                                                                                                               |
| **Beta-Binomial Predictive Rule**           | A Bayesian alternative for empirical regression: the predictive distribution of the test count given the baseline counts and a prior. More powerful than the Fisher rule in most cells, but not calibrated (it exceeds $\alpha$ in some cells) and requires a prior; considered and not adopted. See [Statistical Companion](STATISTICAL-COMPANION.md) §4.5.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Bonferroni Union Bound**                  | $P(\text{at least one false positive}) \le \sum_i \alpha_i$, valid under any dependence among the tests. The methodology's default family-wise statement: disclosed as a bound, not used to rescale per-criterion $\alpha$. See **Type-I Envelope**; [Statistical Companion](STATISTICAL-COMPANION.md) §7.3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Breach Probability**                      | In `latency/precedence`: the probability, with no degradation, that the test's nearest-rank percentile exceeds the baseline's $k$-th order statistic. A finite sum that depends only on ranks, not on the latency distribution. See **Precedence Rank**; [Statistical Companion](STATISTICAL-COMPANION.md) §12.4.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Calibration Certification**               | A separate asset published with each mavai-R release from 0.11.0 (never inside the case files) giving the exact error probabilities of each decision rule over a grid of configurations — the false-degradation-signal probability $A(p)$ of `regression/fisher`, the breach probability of `latency/precedence`, the false-compliance probability of `compliance/exact-binomial`. Evidence that the reference implementation realises the rules' theorems. A framework that claims calibration must name the certification it relies on. See **Formula-Value Conformance**; [Statistical Companion](STATISTICAL-COMPANION.md) §10.6.                                                                                                                                                                                                                                               |
| **Categorical Clause**                      | A service-contract clause stating an obligation or prohibition that holds *with certainty*, not in distribution — e.g. a prohibition on producing illegal content, or a requirement that every response carry an audit identifier. Discharged architecturally (interposed components, structural guarantees) rather than by rate estimation; not promotable from a rate-bounded clause by letting $p^*_c \to 1$. The rate-bounded machinery does not apply. Recognised in exactly one form — **zero-failures** — evaluated observationally. See [Statistical Companion](STATISTICAL-COMPANION.md) §"Clause Forms".                                                                                                                                                                                                                                                                  |
| **Clopper–Pearson Bound**                   | The exact binomial confidence bound, obtained by inverting binomial tests; its coverage is at least the nominal level, so it is conservative. The one-sided lower bound is at least $p_{\mathrm{req}}$ exactly when `compliance/exact-binomial` passes, so it is the interval form of the compliance decision; the upper bound is at most $p_{\mathrm{req}}$ exactly when the SMOKE rule FAILs. Also gives the guardrail sensitivity and specificity bounds. Wilson remains the descriptive interval everywhere else. See [Statistical Companion](STATISTICAL-COMPANION.md) §2.3.3.                                                                                                                                                                                                                                                                                                 |
| **Clustered Sampling Design**               | A workload in which $J$ inputs are each invoked $r$ times ($n = rJ$), so trials of the same input are correlated and carry less evidence than $n$ independent draws. Modelled hierarchically, $X_{ij} \mid \theta_j \sim \mathrm{Bernoulli}(\theta_j)$. Trial records carry design metadata (`promptId`, `stratumId`, `repetitionsPerPrompt`, `samplingMode`, `targetEstimand`, `populationClaim`, ...). Under VERIFICATION, material cluster structure requires an approved estimator matched to the target estimand, a demoted claim, or INCONCLUSIVE; otherwise it is a hard invalidator. See [Statistical Companion](STATISTICAL-COMPANION.md) §8.2, §8.2.1.                                                                                                                                                                                                                    |
| **Compliance Testing**                      | The **compliance / assurance procedure**: an affirmative test that a system meets a normative threshold $p_{\mathrm{req}}$ given by contract, SLA, SLO, policy, or regulation. The hypothesis is $H_0: p \le p_{\mathrm{req}}$ vs $H_1: p > p_{\mathrm{req}}$, decided by `compliance/exact-binomial` (see **Exact Binomial Test**); the controlled error is **false compliance**. A FAIL means compliance was not demonstrated, not that the rate is below the requirement. Distinct in error semantics from the regression procedure (see **Conformance Testing**). See [Statistical Companion](STATISTICAL-COMPANION.md) §3.2, §3.6.                                                                                                                                                                                                                                             |
| **Composite Verdict**                       | The structural composite of a set of verdicts: PASS if every component passes, FAIL if any fails, INCONCLUSIVE otherwise. Applied over a contract's criteria ($V_{\text{rate}}$), over latency constraints ($V_{\text{latency}}$), and over the enforced dimensions ($V_{\text{test}}$). The per-criterion verdicts are retained on the composite, never collapsed to a boolean. See **Test Verdict**; [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.6, §12.3.2.                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Conditional Containment Model**           | The statistical model of architectural discharge: the residual probability that prohibited content reaches the consumer is $p_{\mathrm{residual}} = p_{\mathrm{harm}} \cdot p_{\mathrm{miss}\mid\mathrm{harm}}$. A guardrail experiment bounds the conditional miss probability $p_{\mathrm{miss}\mid\mathrm{harm}}$; it does not estimate the generator's harm prevalence $p_{\mathrm{harm}}$, which requires observing pre-guardrail output. For several boundaries in series, individual miss probabilities must not be multiplied without a justified conditional-independence model. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5b.                                                                                                                                                                                                                            |
| **Confidence**                              | The confidence level $1 - \alpha$: a long-run property of the procedure over repeated runs in a stated random experiment — not the probability that a particular verdict is correct. Part of the parameter triangle. See **Confidence Statement**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Confidence Statement**                    | The one-line plain-language statement accompanying an inferential verdict, naming what $\alpha$ controls and the random experiment it describes. Regression: if the baseline and the test were both drawn afresh from an unchanged service, the procedure would signal degradation with probability at most $\alpha$. Compliance: if the true rate were at or below the requirement, the test would falsely declare compliance with probability at most $\alpha$. Not a posterior probability about the individual verdict. See [Statistical Companion](STATISTICAL-COMPANION.md) §7.2.                                                                                                                                                                                                                                                                                             |
| **Confidence-First Approach**               | Risk-driven: the user specifies $\alpha$, target power and a design alternative rate (or `minDetectableEffect`); the framework computes the required sample size by exact search against the operative decision rule. See [Statistical Companion](STATISTICAL-COMPANION.md) §6.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Configuration Error**                     | A named refusal before any sample runs, distinct from a failure of the system under test: `TEST_LARGER_THAN_BASELINE` (a test planned larger than the baseline run it consumes; any intent; a design policy, not a statistical necessity) and `COMPLIANCE_INFEASIBLE` (a normative design below $N_{\min}$; VERIFICATION only). Every applicable code is reported, in that order; a test with any invalid part is refused whole. Hard invalidators under VERIFICATION also end in a configuration error. Distinct from the sizing declines `ZERO_BASELINE`, `BASELINE_TOO_SMALL` and `ALTERNATIVE_NOT_BELOW_BASELINE`. See [Statistical Companion](STATISTICAL-COMPANION.md) §5.7.1, §8.4.5.                                                                                                                                                                                        |
| **Conformance**                             | The overall assessment of whether a service contract's outcome satisfies its configured criteria across all dimensions. The functional dimension partitions into per-criterion verdicts (each criterion hosting one or more postconditions); the latency dimension carries percentile constraints. The contract's composite verdict is assembled from the per-criterion verdicts under the rules of §1.4.6 of the [Statistical Companion](STATISTICAL-COMPANION.md). Not to be confused with a framework's conformance to the mavai-R reference data (see **Formula-Value Conformance**).                                                                                                                                                                                                                                                                                           |
| **Conformance Testing**                     | The **regression / monitoring procedure** (the Statistical Companion's name): a test that detects degradation from a measured baseline of $K_b$ successes in $n_b$ trials. The hypothesis is $H_0: p_t \ge p_b$ vs $H_1: p_t < p_b$, decided by `regression/fisher` (see **Fisher Exact Test**): PASS iff the test count $K_t$ reaches the regression cutoff $c$. The controlled error is the **false degradation signal**, with the baseline count and the test count both random. A PASS means "no degradation signal at this cutoff", not equivalence to the baseline. Distinct in error semantics from the compliance procedure (see **Compliance Testing**). See [Statistical Companion](STATISTICAL-COMPANION.md) §3.2, §3.4.                                                                                                                                                 |
| **Contract Reference**                      | Human-readable string identifying the document or clause defining a test threshold (e.g., "SLA v3.2 §5.1.2").                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Covariate**                               | A contextual factor that drives variance in system behavior. Covariates are declared on a service contract to indicate which environmental or configuration variables should be tracked for baseline matching and statistical comparison. Unlike functional inputs (factors), covariates represent conditions that affect outcomes but are often outside direct control. Declaring none is itself a declaration that behaviour does not depend on the environment.                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Covariate Category**                      | Classification of a covariate by its nature: temporal (time-based), configuration (deliberate choices), external dependency (third-party services), infrastructure (execution environment), operational (runtime conditions), or data state (data context).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Covariate Conformance**                   | The degree to which a test's covariate values match those of the baseline. Full conformance means all covariates match; non-conformance indicates the test ran under different conditions than the baseline was established. A non-critical mismatch is a minor caveat; an unmatched critical covariate is a major caveat under VERIFICATION (see **Severity Levels**).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Covariate Profile**                       | An immutable record of covariate values captured at a specific point in time, used to characterize the conditions under which an experiment or test was executed. A baseline's resolved covariate profile is part of its index and applies to the baseline as a whole, not per criterion.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Criterion**                               | The partition unit of the functional dimension of a service contract. Hosts one or more postconditions, declares a mode (inferential or observational), the experiment or test in which it is exercised, and — where inferential — a threshold and error level $\alpha_c$. Applied to the run's sampling, each criterion yields its own per-trial Bernoulli stream and is reduced to its own verdict. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.2.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Decision Rule**                           | The versioned procedure that decides an assertion, named on every verdict: `regression/fisher` v1 (empirical regression), `compliance/exact-binomial` v1 (normative compliance), `compliance/smoke-exact-binomial` v1 (normative compliance under SMOKE), `latency/precedence` v1 (latency regression), `latency/compliance-exact-binomial` v1 (explicit latency requirement) and `latency/smoke-compliance-exact-binomial` v1 (explicit latency requirement under SMOKE). The withdrawn 1.4.1 rules survive in mavai-R only, as `regression/wilson-reference` and `latency/order-statistic-bound`, to reproduce historical outputs. See [Statistical Companion](STATISTICAL-COMPANION.md) §9.                                                                                                                                                                                      |
| **Denominator Policy**                      | Withdrawn in Statistical Companion 1.3.1. A criterion's denominator is the full sampling: a trial that produced no testable value (malformed output, timeout, refusal, missing required material) is a FAIL carrying its reason, never excluded. The share of trials that did produce one is the observation rate $r_{c,\mathrm{obs}}$, a diagnostic (§1.5.2). See **Effective Denominator**; [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5a.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Design Alternative Rate**                 | $p_{\mathrm{design}}$ (`designAlternativeRate`): the true rate at which a test must reach its target power. For **regression** it lies below the baseline rate — the degraded rate to be detected; it is not a tolerance, and the test still flags any degradation. For **compliance** it lies above the requirement — an assurance alternative $p_1$, from the margin $p_{\mathrm{req}} + \delta$, else the midway rate $(p_{\mathrm{req}} + 1)/2$, or declared directly; the report names which. See [Statistical Companion](STATISTICAL-COMPANION.md) §5.6.                                                                                                                                                                                                                                                                                                                      |
| **Design Power vs Resolved-Test Power**     | The two exact regression powers at the design alternative rate, always named apart. **Design power** averages over a baseline yet to be drawn (baseline and test planned together); **resolved-test power** fixes the cutoff from the baseline count actually observed. They can disagree. The required sample size is the smallest $n$ from which power *stays* at the target for every larger test, since exact power is a sawtooth in $n$. See [Statistical Companion](STATISTICAL-COMPANION.md) §5.3, §5.4.1.                                                                                                                                                                                                                                                                                                                                                                   |
| **Dimension (Functional, Latency)**         | The two quality dimensions of a test. **Functional** (correctness): the binomial model, partitioned into criteria, verdict $V_{\text{rate}}$. **Latency** (temporal): non-parametric percentiles of successful latencies, verdict $V_{\text{latency}}$. Distinct as concerns but not assumed statistically independent; combined by logical conjunction. See [Statistical Companion](STATISTICAL-COMPANION.md) §"Two Dimensions of Stochasticity", §12.7.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Displayed Rate**                          | $c/n_t$: the regression cutoff expressed as a rate, reported to a fixed precision (typically six decimal places) for readability. Informational only; the binding decision is on the integer count. See [Statistical Companion](STATISTICAL-COMPANION.md) §3.4, §5.1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Duration Constraint**                     | A timing requirement in a service contract specifying the maximum allowed execution duration. Evaluated as an independent aspect of conformance alongside postconditions and expected-output matching.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Effect Size**                             | The degradation the test is designed to detect (same as minimum detectable effect). See **Design Alternative Rate**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Effective Denominator**                   | $n_c = N$: every sample is seen by every criterion, so a criterion's denominator is the full sampling. A trial is a success only on a clean PASS; a trial with no testable value is a FAIL (reason transform/no-value), never excluded. Observational criteria carry no rate denominator. The only legitimate narrowing in the methodology is the latency population. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5a.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Effective Sample Size**                   | $n_{\mathrm{eff}} = n / (1 + (n-1)\rho)$: the number of independent trials whose evidence equals that of $n$ trials sharing pairwise correlation $\rho$. A first-cut sanity check only; real workloads are better described by a clustered design. See [Statistical Companion](STATISTICAL-COMPANION.md) §8.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Empirical Baseline**                      | Machine-generated record of observed behavior from a measure experiment: the statistical object linking measurement to inference. A family of per-criterion counts $(K_c, n_c)$ and estimates $\hat p_c$ from one measure run over one sampling, qualified by the factor record, covariate profile, structural reference and optional expiration window. Stores counts, not merely rates, because the Fisher cutoff needs them. Cutoffs and $\alpha$ are not part of it; the consuming test derives them at resolution time. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.5.                                                                                                                                                                                                                                                                                            |
| **Empirical Clause** *(deprecated)*         | Former name for **Rate-Bounded Clause**; the word *empirical* is now reserved for the threshold **origin** (see *Threshold Origin*, *Form vs Origin*). See **Rate-Bounded Clause**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Empirical Percentile**                    | A quantile estimated directly from observed data without assuming a parametric distribution. In the mavai methodology, latency percentiles are computed using the nearest-rank method from the order statistics of successful-response latencies. See also: Nearest-Rank Method, Order Statistic.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Enforcement Mode**                        | Whether the assertions of a dimension, functional or latency, can fail the test (enforced) or are decided by their rules and reported without failing it (advisory). Every assertion is enforced by default, whatever its threshold source; a run-time switch, never a per-test annotation, makes the functional dimension, the latency dimension or both advisory (Statistical Companion §12.6).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Epistemic Status**                        | The label the Statistical Companion attaches to every formula and device: *exact*; *exact conditional test*; *Wilson score construction* (descriptive only); *asymptotic / normal approximation* (planning only); *heuristic*; *non-parametric / distribution-free*. It also separates exact statistical results from operational approximations and from engineering guardrails, which are design policies without calibration guarantees. See [Statistical Companion](STATISTICAL-COMPANION.md) §"What This Document Contains", §9.                                                                                                                                                                                                                                                                                                                                               |
| **Exact Binomial Test**                     | The one-sided exact binomial test, `compliance/exact-binomial`: decides normative compliance. PASS iff the success count $K$ reaches the compliance count $k_{\min} = \min\{k : P_{p_{\mathrm{req}}}(K \ge k) \le \alpha\}$. The false-compliance probability is at most $\alpha$ exactly, at every sample size. Equivalent to the Clopper–Pearson lower bound reaching $p_{\mathrm{req}}$. The same test on the within-threshold count decides an explicit latency requirement; with the null reversed it is the SMOKE rule. See [Statistical Companion](STATISTICAL-COMPANION.md) §3.6.                                                                                                                                                                                                                                                                                           |
| **Exact-Boundary Convention**               | When a computed probability lies within a relative $10^{-9}$ of $\alpha$, it is recomputed exactly in rational arithmetic from the declared inputs (reading 0.05 as 1/20) and the rule's inclusive comparison is applied to the exact value. The mavai-R fixtures carry named exact-boundary cases that fail an implementation comparing doubles alone. See [Statistical Companion](STATISTICAL-COMPANION.md) §10.6.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Expected-Output Match**                   | Comparison of a service contract's actual response against a known expected result using a configurable matcher strategy (exact, case-insensitive, JSON-structural, or custom). The strongest form of correctness check: not "is the response valid?" but "is the response *this specific value*?" One independent aspect of conformance.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Experiment**                              | A controlled execution of a service contract to characterise system behaviour. Three modes exist: explore (compare configurations), measure (establish baselines), and optimize (tune parameters).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Experiment Configuration**                | One concrete combination of factor values — the unit of execution in an explore experiment.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Experiment Design**                       | Declarative description of what is explored (factors + levels).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Explicit Latency Requirement**            | A normative latency threshold: "the $p$-th percentile of successful latencies is at most $\tau$". Decided by `latency/compliance-exact-binomial`, the exact binomial test applied to the within-threshold count $Y = \#\{i : t_i \le \tau\}$: PASS iff $Y \ge y_{\min}$. Comparing the observed percentile with $\tau$ (the *raw comparison*) supports no compliance claim and is reported only as a labelled figure. Under SMOKE, decided by `latency/smoke-compliance-exact-binomial`. See [Statistical Companion](STATISTICAL-COMPANION.md) §12.3.4.                                                                                                                                                                                                                                                                                                                             |
| **Explore Experiment**                      | Experiment mode that compares multiple configurations with fewer samples each.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Factor**                                  | One independently varied dimension in an explore experiment (e.g., model, temperature).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Factor Level**                            | Design-of-Experiments term for one setting of a factor. **Not canonical mavai terminology** — kept here only as a nod to the DoE roots of the methodology. In mavai prose, code, and documentation, use "factor value" instead. A Factor has values; an Experiment Configuration is one combination of factor values.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Factor Record**                           | The provenance of what a baseline measured: service deployment, model, temperature, system prompt, serving configuration and other observable endpoint and deployment metadata. Qualifies the baseline but is not part of its index, unless the relevant factors are also declared as covariates. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.3.1, §1.5.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **False Compliance**                        | The error event controlled by the compliance procedures: declaring compliance when the true rate is at or below the requirement. Bounded by $\alpha$. See [Statistical Companion](STATISTICAL-COMPANION.md) §3.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **False Degradation Signal**                | The error event controlled by the regression procedures: signalling degradation when the service has not changed. Calibrated in the experiment where the baseline count and the test count are both drawn afresh under one unchanged success probability; there, the probability $A(p)$ is at most $\alpha$. A probability computed with the baseline held at its observed rate is only a labelled diagnostic. See [Statistical Companion](STATISTICAL-COMPANION.md) §3.2, §3.4.                                                                                                                                                                                                                                                                                                                                                                                                    |
| **False Discovery Rate (FDR)**              | Optional control for exploratory families of decisions: Benjamini–Hochberg (under independence or PRDS) or Benjamini–Yekutieli (under arbitrary dependence). Applied within one direction only; never imposed. See [Statistical Companion](STATISTICAL-COMPANION.md) §7.3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **False Negative (Type II Error)**          | A test pass when the system has degraded. Its rate $\beta$ depends on the true effect size, the sample sizes and the cutoff; $1 - \beta$ is the power.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **False Positive (Type I Error)**           | A test failure when the system has not degraded. Its rate is bounded by $\alpha$; for regression the error event is the **false degradation signal**, for compliance the error controlled is **false compliance**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Family of Contracts**                     | The contracts that evidence one business service over several input populations, each exercised by its own test over its own sampling. A view across them is reporting, not a verdict; their samplings are never pooled. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.7, §1.4.8.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Feasibility Gate**                        | Pre-execution check that a normative (compliance) design can PASS at all: under the exact rule, only if $n \ge N_{\min} = \lceil \log\alpha / \log p_{\mathrm{req}} \rceil$. Under VERIFICATION an infeasible design is refused before any samples are collected (`COMPLIANCE_INFEASIBLE`); under SMOKE it runs and is decided by the SMOKE rule. Feasible means PASS is possible, not that the test is adequately powered. See [Statistical Companion](STATISTICAL-COMPANION.md) §5.7.1.                                                                                                                                                                                                                                                                                                                                                                                           |
| **Fisher Exact Test**                       | The one-sided Fisher exact test, `regression/fisher`: decides empirical regression. Compares the test's success count $K_t$ with the baseline's $K_b$ through the hypergeometric lower tail given their pooled total, so no estimate of $p$ is needed. A test count FAILs iff its p-value is at most $\alpha$; the **regression cutoff** $c$ is the smallest count whose p-value exceeds $\alpha$, and PASS iff $K_t \ge c$. Exact conditionally, conservative unconditionally: the false-degradation-signal probability is at most $\alpha$ with baseline and test both random. Replaced Wilson-based threshold derivation in companion 1.5.0. See [Statistical Companion](STATISTICAL-COMPANION.md) §2.5, §3.4.                                                                                                                                                                   |
| **Footprint**                               | A stable hash identifying the combination of service contract identity, functional parameters, and covariate declarations. Two baselines with the same footprint are candidates for covariate-based selection.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Form vs Origin**                          | Two orthogonal axes describing a clause. **Form** — rate-bounded vs categorical — is *what kind of proposition* the clause states. **Origin** — normative vs empirical — is *where a rate-bounded threshold came from*. The word *empirical* names a value on the origin axis only; it is not a form. See [Statistical Companion](STATISTICAL-COMPANION.md) §"Clause Forms".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Formula-Value Conformance**               | One of two conformance statuses a framework reports against the mavai-R oracle: its integer decision artefacts agree with the fixtures exactly and its other outputs within the stated tolerance. **Statistical calibration conformance** additionally relies on, and names, the published calibration certification. The two are kept apart in the report's `conformanceStatus`. See [Statistical Companion](STATISTICAL-COMPANION.md) §10.6.                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Guardrail**                               | Used in two senses. (1) An **architectural boundary** — a classifier, filter or gate interposed between a stochastic generator and its consumer to discharge a categorical clause (see **Architectural Discharge**). (2) An **engineering guardrail** — a framework discipline (covariate tracking, baseline expiration, provenance, feasibility gating, warnings) that makes assumption violations visible without repairing them. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5b, §8.4.                                                                                                                                                                                                                                                                                                                                                                            |
| **Guardrail Sensitivity and Specificity**   | **Sensitivity** $s$: the probability that a guardrail blocks a harmful candidate presented to it, estimated over a harmful-candidate sampling with a Clopper–Pearson lower bound $L_s$, giving the miss-probability bound $U_{\mathrm{miss}} = 1 - L_s$. **Specificity**: the probability that it allows non-harmful content, estimated over a non-harmful challenge sampling; it controls over-refusal. Reported as separate criteria. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5b.                                                                                                                                                                                                                                                                                                                                                                              |
| **Harmful-Candidate Sampling**              | Prohibited candidate outputs presented directly to a guardrail; estimates its conditional miss probability $p_{\mathrm{miss}\mid\mathrm{harm}}$ and says nothing about how often the generator emits such content. Distinct from a **red-team-input sampling** — adversarial prompts submitted to the whole generator-plus-guardrail application, which measures end-to-end behaviour under adversarial prompting. The two are never conflated in reporting. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5b.                                                                                                                                                                                                                                                                                                                                                         |
| **Hypergeometric Distribution**             | The conditional law of the test's success count given the pooled total of two binomial counts with a common $p$; it does not depend on $p$. Its lower tail is the one-sided Fisher p-value. See [Statistical Companion](STATISTICAL-COMPANION.md) §2.5.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Implied α**                               | In the threshold-first approach, the $\alpha$ a declared threshold corresponds to. Regression: the smallest $\alpha$ at which the Fisher rule yields the declared cutoff (the p-value of $c - 1$); a declared cutoff with implied $\alpha$ above 0.20 is reported as unsound. Compliance: the exact p-value of the observed count. See [Statistical Companion](STATISTICAL-COMPANION.md) §6.3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Indicative Result**                       | A latency percentile computed, under SMOKE intent, from fewer successful samples than the minimum for that percentile level. The result is reported but explicitly qualified as a directional signal, not a statistically reliable estimate. Under VERIFICATION the same case is INCONCLUSIVE. Analogous to the smoke/verification asymmetry for pass-rate testing. See [Statistical Companion](STATISTICAL-COMPANION.md) §12.5.4.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Inferential Mode**                        | Criterion mode that estimates the true rate of the criterion and decides against a threshold at error level $\alpha_c$ by the criterion's decision rule — `compliance/exact-binomial` for a normative threshold, `regression/fisher` for an empirical one; the Wilson interval is reported as description only. Produces a three-valued verdict (PASS, FAIL, or INCONCLUSIVE). Appropriate for criteria whose contractual question is "what is the true rate of behaviour, with what confidence, and does it clear the demanded threshold?" See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5.                                                                                                                                                                                                                                                                           |
| **Inferential Reach**                       | A criterion's verdict is primarily a claim about the $N$ samples of the sampling its run used. Extending it to another input distribution — production traffic, or a superpopulation the sampling is taken to represent — is the reader's interpretive move and needs further evidence. Every verdict names its sampling. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.7.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Input Source**                            | The population from which per-sample inputs are drawn, cycled round-robin across samples.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Instance Conformance**                    | Expected-output matching against a golden dataset of known-correct results, using a configurable matcher strategy (exact, case-insensitive, JSON-structural, or custom). One aspect of overall conformance. See: Expected-Output Match.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Integer Decision Artefact**               | The integer that decides a verdict, never a rounded displayed rate: the regression cutoff $c$, the compliance count $k_{\min}$, the SMOKE count $k_{\text{smoke}}$, the latency compliance count $y_{\min}$ (or $y_{\text{smoke}}$), and the latency rank $k$ (or `saturated`). Two implementations make the same decision iff their integer artefacts agree. See [Statistical Companion](STATISTICAL-COMPANION.md) §3.4, Appendix A.                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Latency Assertion**                       | A set of percentile constraints $\{(p_j, \tau_j)\}$ over the latencies of successful samples, each with an explicit or baseline-derived threshold in milliseconds. Each constraint is decided by the rule for its threshold source — an explicit threshold by `latency/compliance-exact-binomial`, a baseline-derived one by `latency/precedence` — and the latency verdict $V_{\text{latency}}$ is their structural composite: PASS if every constraint passes, FAIL if any fails, INCONCLUSIVE otherwise. See [Statistical Companion](STATISTICAL-COMPANION.md) §12.3.                                                                                                                                                                                                                                                                                                            |
| **Latency Population**                      | The conditional distribution of execution times given success: $T \mid S = 1$, where $S$ is the conjunction of the contract's functional criteria. Only successful samples — those passing every functional criterion — contribute a *successful latency*. Failed samples (fast rejections, timeouts, wrong or malformed responses) are excluded because their execution times are not comparable with successful-response latencies. See **Tripartite Contract**; [Statistical Companion](STATISTICAL-COMPANION.md) §12.2.1.                                                                                                                                                                                                                                                                                                                                                       |
| **Latency Threshold Derivation**            | Deriving a latency threshold from a baseline, by `latency/precedence`: $\tau = t_{(k)}$, the $k$-th smallest baseline latency, with $k$ the smallest rank whose breach probability for the test that will run is at most $\alpha$. Calibrated for the test's own sampling variation, distribution-free, and an observed integer-millisecond value. Until companion 1.5.0 the threshold was the binomial order-statistic upper confidence bound on the baseline's quantile, which ignored the test's variation and is withdrawn. See **Precedence Rank**; [Statistical Companion](STATISTICAL-COMPANION.md) §12.4.                                                                                                                                                                                                                                                                   |
| **Measure Experiment**                      | Experiment mode for precise estimation of one configuration with many samples, establishing an empirical baseline. Should be at least as large as any test that consumes its baseline.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Minimum Detectable Degradation**          | Reported when a regression test declares no design alternative: the smallest drop $\delta$ at which power reaches 0.80 under the operative rule. The report says whether it inverts the design power or the resolved-test power. See [Statistical Companion](STATISTICAL-COMPANION.md) §5.6.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Minimum Detectable Effect**               | `minDetectableEffect` ($\delta$): a directional way of stating the design alternative rate — for regression the degradation $p_b - p_{\mathrm{design}}$ below the baseline, for compliance the assurance margin above the requirement. Required for the confidence-first approach to compute a sample size. See **Design Alternative Rate**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Minimum Pass Rate**                       | The threshold pass rate the system must meet to pass the test. Part of the parameter triangle.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Minimum Sample Size (Latency)**           | The minimum number of successful samples required for a percentile estimate to be non-degenerate (the non-degeneracy gate). Values: p50 → 5 (an engineering minimum), p90 → 10, p95 → 20, p99 → 100. Below these thresholds the percentile collapses to the maximum (or minimum) of the sample and provides no distributional information. Necessary but not sufficient for a precedence rank to exist; does not apply to an explicit latency requirement. See [Statistical Companion](STATISTICAL-COMPANION.md) §12.5.                                                                                                                                                                                                                                                                                                                                                             |
| **Monitoring Horizon**                      | The number of invocations $H$ — runs, a wall-clock window, or release gates — over which a recurring monitor's false-alarm probability is stated. A per-run $\alpha$ is not a horizon-level claim; the dependence-robust bound is $H\alpha$, ex ante over the baseline's generation. One historical false alarm is not by itself evidence of method failure. See **Reference-State Epoch**; [Statistical Companion](STATISTICAL-COMPANION.md) §8.5.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Nearest-Rank Method**                     | Percentile computation method $Q(p) = t_{(\lceil p \cdot n_s \rceil)}$, the rank clamped to $[1, n_s]$ (zero-based index ⌈p·n⌉ − 1, clamped to [0, n−1]). Produces integer-valued percentile estimates from the order statistics, aligning naturally with latency thresholds expressed in integer milliseconds. Preferred over linear interpolation methods (e.g., R's Type 7) for this reason.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **NO FAILURE OBSERVED**                     | A label that may replace "PASS" on a high-consequence observational criterion below an operator-configured minimum probe count. A label change only; the verdict semantics are unchanged. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Non-Parametric**                          | A statistical method that makes no assumptions about the shape of the underlying distribution. The mavai latency analysis is entirely non-parametric: percentiles are estimated directly from order statistics rather than by fitting a parametric model (e.g., normal, log-normal) to the data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Non-Stationarity**                        | A success probability that is not constant: within-experiment drift, between-experiment drift, contextual variation, or gradual degradation. No framework can guarantee stationarity; covariates make known context changes visible and baseline expiration bounds unknown drift in time. See [Statistical Companion](STATISTICAL-COMPANION.md) §8.3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Normative Threshold**                     | A threshold origin that represents a requirement (SLA, SLO, or policy), decided by the compliance procedure. With verification intent, a design too small for PASS to be possible is rejected before execution; with smoke intent, the test runs and is decided by the reversed SMOKE rule, which FAILs only on evidence of non-compliance.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Observational Mode**                      | Criterion mode that reports whether any failure of the criterion was observed in the run. No population estimation, no confidence interval, no threshold parameter. Appropriate for criteria where any failure is consequential — typically the observational zero-failures criterion that provides evidence for a categorical clause discharged architecturally. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **One-Sided Lower Bound**                   | Statistical threshold below which the true success rate is unlikely to fall at a given confidence level. The exact (Clopper–Pearson) form is the interval form of the compliance decision; the Wilson form is descriptive.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **Optimize Experiment**                     | Experiment mode that iteratively tunes a single factor to find the optimal value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Order Statistic**                         | The k-th smallest value in a sorted sample. The notation t₍ₖ₎ denotes the k-th order statistic. Empirical percentiles are specific order statistics selected by the nearest-rank index formula.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **P-Value Alignment**                       | Any p-value in a report is the tail probability of the same test and orientation as the decision rule that produced the verdict, and carries its null, alternative and tail; otherwise the report carries no p-value. A Wald-style z-score is at most a labelled diagnostic. See [Statistical Companion](STATISTICAL-COMPANION.md) §7.1.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Parameter Triangle**                      | The three interdependent parameters in probabilistic testing: samples, confidence, and minimum pass rate. You control two; statistics determines the third.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Per-criterion Bernoulli Stream**          | The sequence of per-trial pass/fail indicators that a criterion yields when applied to the sampling. Modelled as i.i.d. Bernoulli with parameter $p_c$ under the methodology's working approximation; the substrate of all per-criterion inference. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Per-Sample Outcome vs Run-Level Verdict** | A criterion's outcome on a **single sample** is two-valued — PASS or FAIL (a FAIL carrying a *condition* or *transform/no-value* reason). Only the **run-level verdict**, aggregated over the whole sampling, is three-valued and may be **INCONCLUSIVE** — when the run cannot support a determination (no count of the observed sample could pass the compliance test, no trials, or an empirical-origin threshold with no baseline rate for the covariates in force). INCONCLUSIVE is a statement about the run, never about any one sample. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5, §1.4.5a.                                                                                                                                                                                                                                                              |
| **Percentile Constraint**                   | A single (percentile level, threshold) pair within a latency assertion — e.g., (p95, 500ms). Decided by its rule: an explicit threshold passes when the within-threshold count reaches $y_{\min}$; a baseline-derived threshold passes when the test's nearest-rank percentile does not exceed $\tau$. Supported levels are p50, p90, p95 and p99.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Perfect Baseline**                        | A baseline with no observed failures, $K_b = n_b$ ($\hat p = 1$). Needs no special case under `regression/fisher`, which uses the counts directly: 1000 of 1000 against a test of 100 at $\alpha = 0.05$ gives $c = 99$. The 1.4.1 Wilson map for this case is withdrawn. See **Zero Baseline**; [Statistical Companion](STATISTICAL-COMPANION.md) §4.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Pinned Snapshot vs Floating Alias**       | A **pinned snapshot** is a model identifier that resolves to fixed weights, removing the dominant source of drift within a run. A **floating alias** is re-bound to newer snapshots and can break stationarity. Testing against pinned snapshots is the prescribed posture — necessary but not sufficient, since the serving stack, routing and safety layers can still change. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.3.1.                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Population Claim**                        | A criterion's declaration of which population its rate $p_c$ generalises to, recorded on the verdict as the `populationClaim` field. Three values: **finite-corpus** (a claim about a fixed enumerated corpus only, either a *realised-run* claim — "$K_c$ of these $n_c$ invocations passed", with no binomial interval — or a *corpus expected-performance* claim about the corpus's expected rate, which needs repeated or prompt-aware analysis; the default for safety-probe and red-team samplings); **superpopulation** (the rate generalises to a named external population, e.g. production traffic — generalisability is argued, not validated, by the operator); **no-generalisation** (the rate describes the run only). A mismatch between baseline and test on this field is a §8.4.5 hard invalidator. See [Statistical Companion](STATISTICAL-COMPANION.md) §8.4.6. |
| **Postcondition**                           | A named predicate over a single trial's output, deciding pass or fail for one observable property. A postcondition carries no threshold and no statistical configuration of its own — it belongs to a criterion (which hosts one or more postconditions), and the criterion supplies the threshold, confidence level and mode under which the postcondition's per-trial verdicts are aggregated. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.2.                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Power**                                   | Probability of a correct alarm: for regression, of detecting a real degradation (1 minus the false negative rate); for compliance, of demonstrating compliance when the true rate is at the assurance alternative. Computed exactly against the operative decision rule. See **Design Power vs Resolved-Test Power**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Precedence Rank**                         | The rank that decides latency regression under `latency/precedence`: the smallest $k \le n_b$ whose breach probability is at most $\alpha$ for a test of $n_t$ successful latencies at the given percentile. The threshold is the baseline's $k$-th order statistic, and the test PASSes iff its nearest-rank percentile does not exceed it. Exact under continuity, conservative under ties, and dependent on the test size. If no rank exists for the actual number of successful latencies, the result is INCONCLUSIVE with `saturated: true`. See [Statistical Companion](STATISTICAL-COMPANION.md) §12.4.2, §12.5.2.1.                                                                                                                                                                                                                                                         |
| **Provenance**                              | The chain of artefacts from definition to enforcement, ensuring every verdict can be traced to its empirical foundation.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Rate-Bounded Clause**                     | A service-contract clause stating a rate-bounded proposition: the criterion's true pass rate $p_c$ must clear a threshold $p^*_c$ at error level $\alpha_c$. Discharged statistically by the exact decision rules — `compliance/exact-binomial` for a normative threshold, `regression/fisher` for an empirical one (§3.4, §3.6). Its threshold's **origin** — normative or empirical — is a separate axis (see *Threshold Origin*, *Form vs Origin*). Not promotable to a categorical clause by letting $p^*_c \to 1$. | **Reference-State Epoch**                   | The period between baseline refreshes: a refresh ends one reference state and begins another. Horizon-level calibrations are computed within an epoch; trends across epochs are descriptive, not inferential. See [Statistical Companion](STATISTICAL-COMPANION.md) §8.5.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Regression Cutoff**                       | $c$: the smallest test success count whose one-sided Fisher p-value exceeds $\alpha$, derived from the baseline's $(K_b, n_b)$, the test size $n_t$ and $\alpha$. PASS iff $K_t \ge c$. Non-decreasing in $K_b$. Derived when the test resolves against the baseline, not stored on the baseline. See **Fisher Exact Test**; [Statistical Companion](STATISTICAL-COMPANION.md) §1.5.4, §3.4.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **Regression Testing**                      | The Statistical Companion's name for the regression / monitoring procedure. See **Conformance Testing**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Regression Threshold**                    | The threshold a regression test applies, derived from baseline data: the integer **regression cutoff** $c$ of the one-sided Fisher exact test, with the displayed rate $c/n_t$ beside it. Until companion 1.5.0 it was derived from the Wilson lower bound; that derivation is withdrawn.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Right-Skewed Distribution**               | A distribution with a long right tail, where the mean exceeds the median. Service latency distributions are typically right-skewed due to cache misses, garbage collection pauses, and cold starts. This is the primary reason the mavai methodology uses non-parametric percentiles rather than parametric models.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Rule of Three**                           | Heuristic: zero failures in $n$ trials gives an approximate 95% upper bound of $3/n$ on the failure probability. May annotate a passing observational verdict, under an explicit i.i.d. Bernoulli caveat, without changing its label. It is also why no finite sample discharges a categorical clause statistically. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5, §4.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Sample**                                  | A single execution of the system under test. Distinct from **Sampling**, which is the list of $N \geq 1$ samples comprising one experiment or test. See also **Trial**.                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Sample Size**                             | Number of test executions; controls cost and time. Part of the parameter triangle.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Sample-Size-First Approach**              | Cost-driven: the user specifies samples + $\alpha$; the framework computes the cutoff (regression) or $k_{\min}$ and feasibility (compliance), and the power or minimum detectable degradation the design affords. | **Sampling**                                | The list of $N \geq 1$ sample inputs posted to the service in a single experiment or test. Displayed thresholds are rounded half-to-even while raw values are retained, and a stable sort is assumed. Each report names its `tiePolicy` and `sortStable`. See [Statistical Companion](STATISTICAL-COMPANION.md) §12.8.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Transform / No-Value Failure**            | A per-trial FAIL reason: no testable value could be produced (malformed output, timeout, refusal, missing required material, or a failed transformation step). Counted as a FAIL, never excluded from the denominator, and distinguished from a *condition* failure only diagnostically. Earlier drafts mislabelled it INCONCLUSIVE at the trial level. The share of trials that did produce a value is the observation rate $r_{c,\mathrm{obs}}$. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5a.                                                                                                                                                                                                                                                                                                                                                                   |
| **Transparent Statistics Mode**             | A report mode exposing the full statistical reasoning behind a verdict: a test-level header (test verdict, per-criterion summary, latency summary, Type-I envelopes), a per-criterion analysis block (hypothesis test, observed data, threshold reference, statistical inference, and a verdict in three strands — statistical verdict, observed-rate status, operational caution), and reproducibility metadata naming the reference-data version, quantile source, interval implementation, sort stability and tie policy. See [Statistical Companion](STATISTICAL-COMPANION.md) §10.                                                                                                                                                                                                                                                                                             |
| **Trial**                                   | Methodology-register synonym for **Sample** (Bernoulli trial). Used in the Statistical Companion and the Statistical Model Overview, in keeping with the statistical literature. The frameworks (punit, feotest) use *sample* in code and per-project documentation. See **Sample**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Tripartite Contract**                     | The decomposition of service-level behaviour into three sub-contracts: **correctness** and **availability** (both binomial; availability currently treated jointly with correctness, or declared as its own criterion) and **latency-given-success** (non-parametric percentiles). Evaluated jointly by logical conjunction, so a service cannot improve its latency by turning slow successes into fast failures (the perverse-incentive hazard). See [Statistical Companion](STATISTICAL-COMPANION.md) §12.2.1.                                                                                                                                                                                                                                                                                                                                                                   |
| **Type-I Envelope**                         | A disclosed union-bound aggregate of the $\alpha$ levels of a test's enforced binding decisions, split by direction: the **false-compliance envelope** (compliance criteria and explicit latency requirements) and the **false-degradation-signal envelope** (regression criteria and baseline-derived latency constraints). Holds under arbitrary dependence. Observational criteria, SMOKE-rule decisions and advisory dimensions contribute nothing. A disclosure, not a control target: per-criterion $\alpha_c$ is not rescaled to meet it. Across-suite envelopes are split the same way. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.6, §7.3.                                                                                                                                                                                                                 |
| **Upper Confidence Bound**                  | A one-sided bound above which the true value is unlikely to lie at a given confidence level. Used in guardrail containment (the upper bound $U_{\mathrm{miss}}$ on a guardrail's miss probability) and remaining available as a descriptive bound on a baseline's latency quantile. It no longer derives latency thresholds: a bound on the baseline's quantile ignores the test's own sampling variation (see **Latency Threshold Derivation**).                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Use Case** *(deprecated)*                 | Former name for **Service Contract**. See **Service Contract**, **Service Contract ID**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Verification (Intent)**                   | Test-intent value declaring an evidential posture: the configuration must be statistically feasible to deliver the affirmative claim demanded by a normative threshold, or the test is rejected by the feasibility gate before execution. Verification verdicts carry the procedure's full error semantics; they are the form of verdict admissible for compliance against SLA, SLO, or policy thresholds. See **Test Intent**; [Statistical Companion](STATISTICAL-COMPANION.md).                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Verdict**                                 | The outcome of a per-criterion or composite evaluation, three-valued: **PASS**, **FAIL**, or **INCONCLUSIVE**. INCONCLUSIVE means no determination could be reached — no count of the observed sample could pass the compliance test, there were no trials, covariates are misaligned, or (for latency) the percentile is degenerate or no precedence rank exists. Contract composite verdicts are assembled from per-criterion verdicts under the rules of §1.4.6. Verdict wording follows the procedure: a regression PASS reads "no degradation signal", a compliance PASS "evidence supports compliance". See [Statistical Companion](STATISTICAL-COMPANION.md) §1.4.5, §1.4.6, §5.1.                                                                                                                                                                                           |
| **Wald Interval**                           | The normal-approximation interval $\hat p \pm z \cdot \text{SE}$. Documented for completeness and not used: it degenerates at the boundary and can leave $[0, 1]$. See [Statistical Companion](STATISTICAL-COMPANION.md) §2.3.2.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Wilson Score Bound**                      | Score-test confidence bound for binomial proportions, stable near 0 and 1 and always inside $[0, 1]$. Since companion 1.5.0 it is the methodology's **descriptive** interval only: it describes the uncertainty around an observed rate and decides no verdict. Where an affirmative claim needs exact calibration, the Clopper–Pearson bound is used instead. See the [Statistical Companion](STATISTICAL-COMPANION.md) §2.3.1 for the full treatment.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Working Approximation**                   | Treating each trial as an i.i.d. Bernoulli outcome with a constant success probability: a modelling assumption, not a discovered truth. It rests on three formal assumptions — independence, stationarity and binary outcomes — and is defensible under stated conditions: a pinned model snapshot, a fixed system prompt and sampling configuration, no conversation state carried between calls, a stable input-sampling process, and a run of bounded duration. See [Statistical Companion](STATISTICAL-COMPANION.md) §1.1, §1.3.                                                                                                                                                                                                                                                                                                                                                |
| **Zero Baseline**                           | A baseline with no observed successes, $K_b = 0$. The Fisher cutoff is $c = 0$ — defined but degenerate, since the test demands nothing — and risk-driven sizing is declined (`ZERO_BASELINE`), because there is no rate below the baseline at which to require power. See [Statistical Companion](STATISTICAL-COMPANION.md) §4.3.4.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Zero-Failures Clause**                    | The single form in which a categorical clause is recognised: the developer declares the expectation while explicitly abandoning any statistical lower bound. Evaluated observationally — PASS if no failure is observed, FAIL on any, INCONCLUSIVE only if there were no trials. Authored as `zeroFailures()` (punit) / `zero_failures()` (feotest). See **Categorical Clause**, **Observational Mode**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
